## 2. 怎么检索（每次写脚本前都该走一遍）

### 2.1 用 `manual/` 里的文本镜像搜（本机没有抽取脚本，也不需要）

说明书原文镜像随本技能一起装好：`manual/`（850 个 `.txt`，**保留原 CHM 的目录结构**）。

```powershell
$m = 'C:\Users\9900k\AppData\Local\Nuphus\plugin\skills\community\lf-engine\manual'
Get-ChildItem "$m" -Recurse -Filter *.txt |
  Select-String -Pattern 'CHECKBAGSIZE' -SimpleMatch |
  Select-Object -First 20 | ForEach-Object { $_.Filename + ':' + $_.LineNumber + '  ' + $_.Line }
```

Mac 工作区那套抽取脚本（解包 / `--find` / `--list` / `--diff`）**本机没有**，也不需要——镜像已在。

### 2.2 按目录定位

镜像保留原结构：`manual\游戏引擎反外挂系统\功能操作命令\`、`…\脚本检测命令\`、`…\兼容HeroM2\`、
`…\特殊触发功能\`、`…\游戏功能详解\`、`…\常见问题解答\`、`…\其他相关资料\`、`…\部分脚本实例\`。

```powershell
Select-String -Path "$m\游戏引擎反外挂系统\功能操作命令\*.txt" -Pattern 'CALL' |
  Select-Object -First 20 | ForEach-Object { $_.Filename + ':' + $_.LineNumber }
```

### 2.3 目录树与逐页清单

`manual\lf-chm-toc.txt`（章节目录树）与 `manual\lf-chm-toc-pages.txt`（逐页清单）随包提供，
可按章节名/关键词先定位页面，再去读那一页的 `.txt`。

> ⚠️ 索引其它地方保留的 `grep -rn '关键字' 路径` 示例来自 Mac（bash）。
> 在 Windows 上等价改写成：`Get-ChildItem 路径 -Recurse -Filter *.txt | Select-String -Pattern '关键字'`。

## 4. 覆盖边界：说明书里**没有**的东西

写运维/部署相关内容前必须记住这条，否则一定会拿说明书去"推断"运维做法：

| 说明书**不覆盖** | 后果 |
|---|---|
| 进程拓扑、启动顺序、端口分配、自启方式 | 运维事实只能实测云服务器 |
| 数据库之外的部署细节（Windows 服务、计划任务、防火墙） | 同上 |
| 备份/回滚策略 | 线上实测：`dbsrc.ini` 里 `AutoBackup=0`、且 `BackList.txt` 指向的备份目录不存在 → **必须自建备份** |
| 引擎 build 与说明书版本的对应关系 | 靠 `M2Server.exe` 文件日期（2026-07-07）与说明书日期（2026-07-08）对齐来推断（**未验证**，但已比旧版贴近） |
| 与本端具体版本的差异 | 说明书是通用文档，本端脚本可能用了文档里没写的写法 |

写脚本时的正确做法：**说明书 → 找命令是否真实存在；本机 Mir 拷贝 → 看本端真实用例；
云服务器 → 最终裁定。**

## 6. 说明书自身的错漏（引用前先看这里）

说明书是多人多年累积维护的，**本身就有笔误与自相矛盾**，各参考文件末尾都留了"未验证/存疑"清单：

- `data/01-脚本命令-*.md` 第 6 节：218 条（例：`take` 两套"检测持久"语义并存；S/N 下标 499 与 999 冲突；`Z0-J499` 疑为笔误）
- `data/02-触发功能-*.md` 第 4 节：20 条（例：攻击触发正文与示例矛盾；魔法 ID 变量 `<$CURRRUSEMAGICID>` / `<$CURRRRUSEMAGICID>` 两种拼写）
- `data/03-配置与数据库-*.md` 第 8 节：25 条（例：物品位置编号两页冲突；`racelmg` 表原文自述"收集于网络"）
- `data/08-2026-07-08增量-*.md`：新版变化页自身的存疑点（逐页标注）

**引用时**：照抄原文，同时把存疑项一并带出；不要替原文"修正"，
也不要拿修正后的写法当成引擎事实。
